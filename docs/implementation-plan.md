# Anima Prompt Studio 分阶段实施计划

> 依据：[产品需求文档](product-requirements.md)
>
> 原则：先打通一条真实可用的个人主链路，再扩展资料库和长期维护能力。

## 1. 实施原则

- 只围绕 Anima_1.1 的个人本地工作流开发。
- 每一阶段都必须形成可独立验证的用户结果，不只完成底层表或占位界面。
- 现有功能先做真实性审计：未接入真实运行链路的开关、按钮和配置，不计为完成。
- 数据迁移采用增量方式，保留现有项目、版本、收藏和用户工作区改动。
- 模型规则、社区经验、个人偏好和单次任务覆盖分层存储。
- 当前不把 ComfyUI 接入作为任何阶段的前置条件。

## 2. 阶段 0：现状收口与数据基线

### 目标

让已有能力、界面状态和持久化事实一致，为后续迁移建立安全基线。

### 工作项

- 盘点并标记当前真实可用、部分可用和占位功能。
- 清理或禁用无实际作用的模型选择、随机模式、自动组合、刷新双语等入口。
- 为现有 SQLite 建立版本化迁移机制和备份前置检查。
- 定义统一的完整配方、结构块、参数来源和资产引用领域模型。
- 补齐项目列表、重新打开和从已有版本继续编辑的最小能力。

### 阶段出口

- 旧数据迁移后仍可读取。
- 用户能保存项目、关闭页面、重新打开并继续。
- UI 不再把未接线能力表现为可用功能。

## 3. 阶段 1：完整配方与 Anima_1.1 档案

### 目标

把当前“提示词输出”升级为可复制、可保存、可追溯的完整 Anima 配方。

### 工作项

- 建立模型档案、任务预设、参数来源和手动覆盖数据结构。
- 内置并可编辑 Anima_1.1 初始档案，不添加 `safe`。
- 实现正向提示词、负向提示词和基础参数的统一编译。
- 展示参数来源与覆盖关系。
- 支持逐项复制和复制完整配方摘要。
- 关键参数变化自动创建版本，普通输入不创建版本。

### 阶段出口

- 任一已保存版本都能还原模型、提示词、参数和来源。
- 相同输入在没有用户覆盖时使用一致的档案规则。
- 用户手动参数始终拥有最高优先级，且不会被静默改写。

## 4. 阶段 2：中文局部修改与锁定机制

### 目标

实现“只改被点名内容”的核心编辑体验。

### 工作项

- 将现有结构扩展到人物身份、外观、服装、表情、动作、互动、场景、镜头、光影、风格、特效、质量和负向约束。
- 增加中文修改指令解析接口。
- 为每次修改生成受影响结构块、锁定结构块和前后差异预览。
- 用户确认后才应用修改并创建新版本。
- 保存指令原文、解析结果和差异；支持撤销、回滚和继续分支。
- 多人物按角色卡拆分，并单独维护互动关系。

### 阶段出口

- “只改服装”“人物不变，换成俯拍”“保留构图，加强夜景氛围”均能稳定命中正确结构块。
- 未点名字段不发生语义漂移。
- 应用前后的变化可以被人清楚核对。

## 5. 阶段 3：参考图片保真分析

### 目标

让普通图片、插画和无原始提示词的 AI 图片都能转成可核对的结构化事实。

### 工作项

- 保留现有多模型原始输出和部分失败策略。
- 增加结论级融合，区分已确认、有冲突和不确定。
- 每条结论关联来源模型和证据状态。
- 加入图片与文字共同输入的覆盖规则。
- 对多人物生成独立角色卡和互动关系。
- 增加明确的“以此图为参考创作”动作，避免资产图片被自动分析。
- 为长任务提供真实阶段进度和后端取消。

### 阶段出口

- 看不清的内容不会被写成确定事实。
- 文字只覆盖点名部分，未点名画面属性尽量保留。
- 任一结论都能回看其来源模型和原始输出。

## 6. 阶段 4：LoRA 一等资产与推荐

### 目标

把 LoRA 从自由文本标签升级为可扫描、可审核、可解释推荐的本地资产。

### 工作项

- 建立 LoRA 档案、分类、触发词、权重、兼容/冲突和示例图片数据结构。
- 支持多个本地目录的只读增量扫描、哈希识别和缺失重连。
- 新增文件进入待审核；旁车元数据优先，文件名推断仅作候选。
- 实现硬规则过滤和基于任务语义的候选排序。
- 实现同类型最小组合、互补建议、冲突和权重警告。
- 将 LoRA 触发词、顺序和权重编入完整配方。
- 记录但不直接固化个人选择历史。

### 阶段出口

- 扫描过程不改动原模型文件。
- 不兼容 LoRA 不进入默认推荐。
- 每条推荐都有可读理由、触发词、建议权重和冲突说明。

## 7. 阶段 5：官方链接研究与本地验证

### 目标

新增模型或 LoRA 时，形成有来源、有审核、有版本差异的使用档案。

### 工作项

- 新增官方链接、精确版本和研究任务入口。
- 按官方、作者、社区和待验证四级保存证据。
- 生成结构化研究草稿，用户审核后发布到正式档案。
- 支持手动和可配置定期版本检查，生成差异报告。
- 新版本建立独立档案，旧项目继续绑定旧版本。
- 自动生成权重扫描、触发词对比和兼容组合测试矩阵。
- 支持上传手动出图结果，并分别保存官方建议、社区经验和本机结论。

### 阶段出口

- 正式档案的关键规则都可追溯到来源或本机测试。
- 未确认研究结果不会影响生成配方。
- 版本升级不会静默改变旧项目结果。

## 8. 阶段 6：资产库、图片与备份恢复

### 目标

把满意结果沉淀为可查找、可复用、可迁移的个人创作资产。

### 工作项

- 保存完整配方和人物、服装、动作、场景、构图、光影、风格等组件。
- 支持封面图和多张补充图。
- 将图片复制到受管理目录，生成缩略图并哈希去重。
- 实现缩略图浏览、关键词搜索和组合筛选。
- 复用资产时创建副本，并保留适用模型和参数信息。
- 实现备份、校验、恢复和恢复后的模型目录哈希重连。
- 备份明确排除模型文件和 API 密钥。

### 阶段出口

- 用户能通过图片和关键词找回过去的有效配方。
- 删除资产不会意外删除本地原图。
- 在另一台 Windows 机器恢复后，可重新扫描并关联已有模型文件。

## 9. 横向工程任务

以下任务贯穿所有阶段：

- SQLite schema migration、事务和崩溃恢复
- 本地路径、密钥、缓存、日志和用户资产与源码隔离
- API 请求/响应 schema 校验和错误分级
- 长任务进度、真正取消和部分失败恢复
- 前端状态与持久化状态一致性
- 单元、集成和 Windows 本地端到端测试
- 活文档与真实 API 的一致性检查

## 10. 推荐实施顺序

严格按 `阶段 0 → 1 → 2 → 3 → 4 → 5 → 6` 推进。

其中阶段 1 和阶段 2 组成最小可用核心：即使暂时没有完整 LoRA 研究和资产库，用户也能完成“输入创意 → 得到完整配方 → 中文局部修改 → 复制 → 保存版本”的主链路。

每个阶段的完成判定以 [验收标准](acceptance-criteria.md) 为准，而不是以页面或数据库表已经创建为准。
