# 本地 LLM 再次翻译设计

## 目标

在最右侧“中英文输出”区域提供一个“本地 LLM 翻译”按钮，让用户手动处理由 AnimaDex 等资源带入后产生的“待本地 LLM 翻译”占位内容。

## 界面

- 按钮放在“中英文输出”标题行右侧，与输出区直接关联。
- 默认文字为“本地 LLM 翻译”。
- 请求运行时按钮禁用并显示“翻译中...”。
- 没有待翻译内容时按钮保持可点击；点击后提示“当前没有待翻译内容”，不调用模型。

## 翻译范围

- 只处理结构块中文字段中以“待本地 LLM 翻译：”开头的内容。
- 已有正常中文内容不重新翻译、不覆盖。
- 英文提示词、权重、锁定状态、来源、置信度和结构块分类保持不变。
- 本次功能固定使用本地 LLM，不跟随当前“本地 LLM / 外部 API”任务选择器。

## 数据流

1. 前端从当前结构块中收集带有待翻译占位符的项目。
2. 前端向新的本地翻译接口发送项目 ID 和对应英文原文。
3. 后端使用当前已配置的本地 LLM，一次返回各项目的中文翻译。
4. 后端严格校验项目 ID 完整、无重复、中文结果非空。
5. 前端只替换成功返回项目的结构块中文字段。
6. 前端通过现有结构块编译逻辑重新生成右侧中英文输出。
7. 当前版本号不增加；这是补齐同一版本的翻译，不是创建新的提示词变体。

## 接口

新增 `POST /api/text/translate-pending`。

请求包含待翻译项目：

```json
{
  "items": [
    {
      "id": "subject",
      "en": "Hatsune Miku"
    }
  ]
}
```

响应包含对应中文：

```json
{
  "item": {
    "translations": [
      {
        "id": "subject",
        "zh": "初音未来"
      }
    ]
  }
}
```

## 错误处理

- 本地 LLM 未启动：显示明确错误，保留全部原内容。
- 模型输出无法解析、缺项、重复或空翻译：整次拒绝应用，保留全部原内容。
- 网络或服务错误：恢复按钮状态，允许再次点击。
- 不做部分应用，避免结构块处于一半翻译、一半失败的不确定状态。

## 验收标准

- 右侧输出区存在“本地 LLM 翻译”按钮。
- 含待翻译内容时，点击后调用本地 LLM 并更新结构块及右侧中文输出。
- 已有正常中文内容保持不变。
- 没有待翻译内容时不调用模型。
- 翻译失败时不修改当前作品数据。
- 后端接口、前端状态更新、静态界面和失败回滚均有自动化测试。
- 使用真实本地 LLM 和至少一个 AnimaDex 资源进行页面验证。
