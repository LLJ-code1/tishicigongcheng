# 本地多模型识图接入设计

日期：2026-06-22

## 目标

将 WD14、JoyCaption 和 Qwen3-VL 从现有 ComfyUI 节点环境中解耦，作为“提示词工程”网页可直接调用的本地图片分析器，并保留已经跑通的 Florence。所有分析器必须处理用户本次上传的真实图片，支持单选、多选及结果合并。

本阶段不接入 ComfyUI 工作流，不安装 DeepSeek-VL2，也不实现外部视觉 API。现有 DeepSeek API 继续用于文本整理、翻译和结构化。

## 本机条件

- GPU：NVIDIA GeForce RTX 4070 Ti SUPER，16GB 显存。
- 磁盘：H 盘约 247GB 可用，G 盘约 206GB 可用。
- 本地文本 LLM 当前占用大量显存，因此视觉模型不可与其无条件同时常驻。
- Florence 已经能够独立运行。
- JoyCaption Alpha Two 与 Beta One FP8 模型文件已经位于现有 ComfyUI 模型目录，接入时复用，不重复下载。
- WD14 与 QwenVL 的 ComfyUI 节点已存在，但模型和网页独立执行器尚未完整接入。

## 模型组合

### Florence

用途：通用画面描述、主体、场景、构图和可见元素概述。

继续复用现有独立 worker，不依赖 ComfyUI 服务是否启动。

### WD14 ConvNextV2

用途：动漫图片的 Danbooru 风格标签、角色特征、服饰、姿态和画面属性。

使用 ONNX Runtime 的 CPU provider，避免占用 GPU。模型与标签表下载到统一的视觉模型目录，网页服务独立调用，不导入 ComfyUI 运行时。

### JoyCaption Beta One FP8

用途：生成较完整、自然语言风格的图片描述，补足 WD14 标签缺少的关系、氛围和叙述信息。

优先复用本机已有 Beta One FP8 模型。使用独立子进程按请求加载；完成后进程退出并释放显存。若 FP8 模型与现有运行库不兼容，再使用本机 Alpha Two 作为兼容回退，不自动重复下载大型模型。

### Qwen3-VL-4B Instruct Q4

用途：人物关系、动作、场景逻辑、文字内容和用户指定问题的综合视觉理解。

使用 Qwen3-VL-4B Instruct GGUF Q4_K_M 及对应 mmproj。模型放置在独立视觉模型目录。通过独立进程调用，完成后退出并释放显存。

## 架构

网页只调用统一接口：

`POST /api/vision/analyze`

请求包含：

- 图片二进制内容或 Base64。
- 文件名与 MIME 类型。
- 用户勾选的分析器 ID。
- 可选的分析说明。

服务端由 `vision_engine` 负责：

1. 校验上传文件和分析器列表。
2. 为每个分析器建立独立任务。
3. 顺序运行 GPU 模型，避免 JoyCaption、QwenVL、Florence 同时争抢显存。
4. WD14 可在 CPU 上运行，但首版仍采用顺序调度，降低排错复杂度。
5. 收集每个模型的原始结果、耗时和错误。
6. 将成功结果交给文本 LLM 合并为结构化中英文提示词。
7. 即使某个分析器失败，也返回其他成功结果，并在界面明确显示失败项。

每个视觉 worker 是独立脚本，输入输出采用 JSON，避免将不同模型的大型依赖直接加载进网页主服务。

## 显存与生命周期

- 模型默认不在后台常驻。
- 用户点击分析后才启动对应 worker。
- 单个 worker 完成后正常退出，操作系统回收 CPU/GPU 内存。
- 多选时按 `WD14 -> Florence -> JoyCaption -> QwenVL` 顺序执行。
- 如果发现本地文本 LLM 占满显存导致视觉模型无法加载，接口必须返回明确的显存不足信息，而不是无限等待。
- 首版不自动关闭用户正在运行的本地 LLM 或 ComfyUI。

## 界面行为

- Florence、WD14、JoyCaption、QwenVL 均显示真实安装状态。
- 未安装或校验失败的模型不可勾选，并显示原因。
- 分析进度逐项显示，例如“WD14 分析中”“JoyCaption 已完成”“QwenVL 显存不足”。
- 结果区保留各模型的独立输出，并提供自动合并后的中英文结构化提示词。
- 用户可重新选择部分模型再次分析同一张已上传图片。
- 不展示尚未接入的外部视觉 API 为可用状态。

## 错误处理

- 图片格式、大小或内容无效：请求开始前拒绝。
- 模型文件缺失：状态接口返回缺失文件列表。
- 依赖缺失：返回需要安装的具体 Python 包。
- 模型超时：终止 worker，并保留其他模型结果。
- CUDA 显存不足：返回可理解的提示，建议关闭 ComfyUI 或本地文本 LLM 后重试。
- 模型输出为空或格式异常：记录原始输出，标记该分析器失败，不伪造结果。
- 文本 LLM 合并失败：仍返回所有视觉模型原始结果。

## 测试与验收

### 自动测试

- 分析器注册、安装状态和缺失文件检测。
- 图片数据必须传入每个 worker，禁止回退到固定演示文本。
- 单模型成功、单模型失败和部分成功。
- 多模型必须顺序调度 GPU worker。
- worker 超时、异常退出和非 JSON 输出。
- 合并失败时保留原始结果。
- 前端安装状态、选择状态、进度和错误展示。

### 真实模型测试

使用至少三张明显不同的真实图片：

1. 单人物动漫图。
2. 多人物动漫图。
3. 场景或物体为主的图片。

每个模型必须单独完成三张图片中的至少两张，并检查输出确实对应图片内容。随后进行一次 Florence、WD14、JoyCaption、QwenVL 四模型组合测试。

### 完成标准

- 四个本地分析器在网页中显示真实状态。
- 每个新增模型至少有一次从网页上传到最终结果的端到端成功记录。
- 两张不同图片不会得到相同的固定结果。
- 组合分析能显示每个模型的独立结果与合并结果。
- Python、JavaScript 自动测试全部通过。
- 开发日志记录模型路径、版本、测试图片、耗时和已知限制。

## 非目标

- 不接入 ComfyUI 工作流。
- 不安装或接入 DeepSeek-VL2。
- 不让所有模型长期常驻后台。
- 不在本阶段实现外部视觉 API。
- 不自动管理或关闭 ComfyUI、本地文本 LLM 等用户进程。
