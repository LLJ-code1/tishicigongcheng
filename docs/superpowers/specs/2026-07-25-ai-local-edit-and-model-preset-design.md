# AI 局部修改与模型预设设计

## 目标

让用户不必阅读或手动定位完整提示词，只需用中文描述希望发生的变化，系统就能理解
完整十三块配方、选择必要的相关结构块、生成最小范围的修改预览，并在用户确认后保存
为新版本。

第一版只支持现有 `Anima_1.1` 出图模型档案，但模型选择和参数加载按可扩展机制实现。

## 产品原则

- 用户的自然语言编辑由已配置的文本模型理解，不再用有限固定词典冒充通用语义理解。
- AI 可以联动修改完成指令所必需的相关块。例如“环境改成破碎城堡，下着大雨”可以
  修改场景环境、光影色彩和道具特效。
- 每个受影响块都必须在预览中显示修改前、修改后和修改原因。
- 未被 AI 声明为受影响的结构块全部保持不变。
- AI 结果只有通过服务端结构、完整性和范围校验后才能展示为可确认预览。
- 文本模型不可用、调用失败或输出无效时，原配方保持不变，并明确提示 AI 修改暂不可用。
- 用户确认预览后才生成新 Recipe；持久化继续使用现有原子工作区提交链路。

## 界面设计

### 出图模型与参数

配方控制台增加“出图模型”选择器。第一版选项只有
`MiaoMiao Harem Anima_1.1`，值为 `anima-1.1-v1`。选择器的数据来自
`GET /api/model-profiles`，不在前端写死未来模型列表。

选择模型档案后：

- 自动载入档案中的 Sampler、Scheduler、Steps 和 CFG 默认值。
- 参数来源显示为“模型推荐”；用户手动改动后显示为“手动覆盖”。
- 提供档案中的候选分辨率供用户主动选择。
- 未经本地验证的候选分辨率明确标记“候选，待验证”，不得称为“最优”或自动选中。
- 第一版模型选择器即使只有一个选项也保持可见，让参数来源和后续扩展方式清楚。

### AI 局部修改

现有“中文最小差异修改”改名为“AI 局部修改”，辅助说明改为：

> 直接描述想改什么；AI 会读取完整提示词，只提出必要修改，确认后保存为新版本。

用户点击“生成修改预览”后，界面进入加载状态。成功结果按结构块逐项显示：

- 结构块中文名称；
- 修改前中文内容；
- 修改后中文内容；
- AI 修改该块的简短中文原因。

预览顶部汇总“将修改 N 个结构块，其余 M 个保持不变”。确认按钮只在预览通过全部
校验时启用。

失败时显示可行动的信息：

- 文本模型未配置或未运行：提示前往“模型与接口”配置或启动；
- 模型输出无法校验：提示重新生成预览，原内容未改变；
- 工作区在请求期间变化：丢弃旧结果并要求重新预览。

## 服务端架构

### 新的 AI 编辑预览流程

`POST /api/text/edit-preview` 保留现有 URL，但请求增加文本模型提供方和目标出图模型：

```json
{
  "instruction": "环境改成破碎城堡，下着大雨",
  "recipe": {},
  "baseRecipeHash": "64位十六进制值",
  "provider": "local",
  "targetModel": "anima"
}
```

服务端执行：

1. 规范化 Recipe 并校验 `baseRecipeHash`，拒绝过期基线。
2. 使用专用 AI 局部修改提示模板，向已配置的 OpenAI 兼容文本服务发送完整十三块、
   用户指令、块定义和 Anima 输出规则。
3. 要求模型返回严格 JSON，只包含受影响块的完整候选内容与修改原因。
4. 校验块 ID 必须来自当前 Recipe、不得重复、不得修改固定模型字段、英文和中文内容
   均非空、原因非空，并拒绝未知字段。
5. 把候选块与原块合并为服务端生成的差异预览；未声明块不进入候选合并。
6. 计算 `resultHash` 与防篡改 `previewHash` 后返回。

响应沿用现有预览安全字段，并为每项差异增加 `reason`。`affectedIds` 来自通过校验的
模型输出，`lockedIds` 是其余所有结构块。

### 确认应用

`POST /api/text/edit-apply` 继续接收 Recipe 与完整预览。服务端不再次调用 AI，而是：

- 验证 `previewHash`；
- 验证 Recipe 仍与 `baseRecipeHash` 一致；
- 只合并 `affectedIds` 中经过签名的 `after` 块；
- 生成追加式编辑历史和新的 Recipe Hash。

AI 调用具有非确定性，因此确认阶段不能重新调用模型来复算预览。预览完整性由服务端
签名式摘要、基线 Hash、严格字段白名单和确认时的逐字段校验保证。

## AI 输出契约

模型必须返回以下结构，不允许 Markdown 包裹：

```json
{
  "changes": [
    {
      "blockId": "scene",
      "en": "a shattered castle in ruins under heavy rain",
      "zh": "暴雨中的破碎城堡废墟",
      "reason": "用户要求替换环境，并加入破碎状态与暴雨天气。"
    }
  ]
}
```

约束：

- `changes` 至少一项，最多十三项；
- 每个 `blockId` 唯一且必须属于 Recipe；
- `en`、`zh` 和 `reason` 为去除首尾空白后的非空字符串；
- 模型应选择表达指令所必需的最少块集合，但允许场景、光影、特效等语义联动；
- 不得返回整份 Recipe、参数、模型档案、版本号或未请求的元数据；
- 与当前内容完全相同的候选视为无效结果，不提供可确认预览。

## 固定词典迁移

现有确定性解析器不再参与产品中的自然语言预览路径，避免部分命中后静默丢失修饰词。
相关代码可以暂时保留用于旧测试或兼容性，但 HTTP 编辑预览必须只走 AI 语义路径。
不提供“模型失败后退回固定词典”的行为。

## 安全与错误处理

- 不把 API Key 写入请求、Recipe、预览、日志或版本历史。
- 对指令、Recipe 和模型响应保持现有大小、深度、重复键和严格 JSON 限制。
- 模型返回的文字只作为数据展示并经过 HTML 转义。
- 任一候选块无效时整份预览失败，不部分应用其余块。
- 网络错误、超时、取消、模型错误和校验错误使用不同错误码，但都不写数据库。
- 并发请求继续使用现有工作区会话和修订检查，迟到结果不得覆盖新状态。

## 测试策略

### Python

- 模型返回场景、光影、特效三个合法变更时，预览只影响这三个块。
- “破碎城堡”完整保留在中英文候选中，不允许退化成普通“城堡”。
- 未知块、重复块、空内容、空原因、额外字段和无变化结果全部拒绝。
- 文本模型不可用或返回非法 JSON 时，返回明确错误且不产生预览。
- 应用阶段接受原始未篡改预览，拒绝修改后的 `after`、`reason`、块列表或旧基线。
- 模型档案列表和解析接口正确返回默认参数及候选分辨率的验证状态。

### Node

- 模型选择器从 API 数据渲染，选择后应用模型默认参数。
- 用户手动修改参数后来源切换为“手动覆盖”。
- 候选分辨率不会自动选择，并显示待验证状态。
- AI 预览渲染中文前后差异、原因、影响数量和保持不变数量。
- 加载、模型不可用、非法结果、过期响应和工作区变化均保持原块不变。
- 只有合法且仍属于当前工作区的预览可以启用确认按钮。

### 回归

运行全部 Python、Node 和脚本测试。使用本地假模型响应完成自动测试，不依赖真实外部
API。最后在 `127.0.0.1:57913` 手动验证模型参数加载、AI 预览、失败提示和确认保存。

## 不在本次范围

- 添加第二个真实出图模型档案；
- 宣称未经本地验证的参数或分辨率为“最优”；
- 自动出图或比较不同参数的图片质量；
- 在 AI 不可用时执行任何固定词典编辑；
- 允许 AI 绕过预览直接写入或保存版本；
- 自动修改 LoRA、Checkpoint、Generation Seed 或 Img2Img Denoise。
