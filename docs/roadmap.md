# 开发路线图

> 目标需求、阶段顺序与完成定义分别以
> [产品需求文档](product-requirements.md)、
> [分阶段实施计划](implementation-plan.md) 和
> [验收标准](acceptance-criteria.md) 为准。本文件保留当前能力摘要和近期方向。

## 已落地

- SQLite 项目、提示词版本、资源、收藏和设置持久化。
- AnimaDex 角色、画师、搜索和缩略图的同源网关。
- 本地 LLM / 外部 OpenAI 兼容 API 配置、探测与调用。
- Anima 结构化双语输出、保真拆解、单块和多块联合再生成。
- 模型驱动全随机提示词。
- WD14、Florence、JoyCaption、Qwen3-VL 本地图片分析与部分失败保留。
- 一键启动、服务状态查询和本地模型启停。
- 提示词模块化、编译导出、原文归档和自动测试。
- 前端实时编译预览、块权重语法、变体对比与矩阵、版本时间线回滚。
- 配方（整组结构块保存/带入）、画师混合器、Tag 联想补全、请求取消。
- 前端渲染统一 HTML 转义；修复 `.gitignore` 误排除 `anima.md` 的问题。
- 本地 HTTP Host/同源/HEAD/请求 framing/严格 JSON/完整图片验证加固。
- 项目、版本、收藏和设置 schema 校验，服务端版本号、稳定冲突响应与密钥不回显。
- 结构块权重入口统一为 0–120，前后端规范化去重口径一致。

## 下一阶段

近期优先完成完整配方和中文局部修改主链路，再推进图片融合、LoRA 资产、
资料研究和长期资产库；不把 ComfyUI 接入作为当前前置条件。

### 现状收口与完整配方

- 核实现有界面控件与真实运行链路，禁用或移除尚未接线的占位能力。
- 建立可迁移的完整配方数据结构和 Anima_1.1 模型档案。
- 支持项目重新打开、参数来源展示、逐项复制和完整配方版本化。

### 中文局部修改

- 通过中文指令定位结构块，执行前展示受影响范围和前后差异。
- 只修改被点名内容，锁定其余块；应用后生成可撤销的新版本。
- 将多人物拆分为角色卡，并单独维护互动关系。

### 图片分析与 LoRA

- 将多模型图片结果整理为已确认、冲突和不确定，而不是只拼接原文。
- 建立 LoRA 档案、本地只读扫描、兼容校验和最小组合推荐。
- 增加官方链接研究、用户审核、版本差异和本地测试记录。

### 参考提示词库

- 完成参考图片、双语提示词、标签、备注和搜索的持久化界面。
- 支持把参考条目带入扩写，同时保留来源信息。

### 数据维护

- 增加 Prompt Studio 数据库备份、恢复和导出。
- 为 AnimaDex 增加导入状态、数据版本和同步时间展示。
- 明确用户素材、验证产物和可重建缓存的生命周期。

### 图片分析体验

- 为长任务提供可取消、可恢复的进度反馈
  （前端取消已完成；后端中断推理待做）。
- 减少多模型结果中的语义重复。
- 在不争抢文本模型显存的前提下提供可选 GPU 加速。

### 工程化

- 建立有效的 Git 仓库元数据与提交基线。
- 把运行状态、缓存、模型和密钥持续隔离在源码之外。
- 增加自动化的文档/API 一致性检查。
