# Anima Prompt Studio 产品需求文档

> 状态：需求基线（部分实施）
>
> 面向版本：个人本地工作台第一阶段
>
> 更新日期：2026-07-17

## 1. 产品定义

Anima Prompt Studio 是一款面向个人使用的 Windows 本地提示词工作台。

用户输入模糊的中文创意、参考图片，或两者的组合；系统识别并保留用户的核心意图，生成适配指定 Anima 模型的完整生图配方。用户可以用自然语言进行局部修改、查看修改差异、管理模型与 LoRA 的使用规则，并把满意结果连同配套图片沉淀为可复用资产。

第一阶段只服务产品所有者本人，不为陌生用户增加注册、教程、云同步、多用户权限和复杂兼容成本。

## 2. 核心结果

产品的首要价值不是“写出看起来丰富的提示词”，而是提高外部实际出图的稳定性：

- 将完整配方复制到 Anima 后，通常能在 1–2 轮手动出图内稳定接近创意。
- 主体、人物特征、画风和构图基本正确。
- 相似输入和相同配方应有可解释、可复用的结果，不依赖偶然抽卡撞图。
- 用户能知道系统保留了什么、补全了什么、改动了什么，以及建议来自哪里。

准确、保真和稳定优先于处理速度。

## 3. 用户与使用环境

### 3.1 目标用户

- 第一阶段唯一用户：产品所有者本人。
- 熟悉 Anima 和本地生图工具，不需要新手教程。
- 主要在 Windows 本地环境中使用。

### 3.2 运行边界

- 默认本地处理和本地存储。
- 当前不接入 ComfyUI 自动生图，由用户复制配方后自行出图和判断效果。
- 外部 API 只能在单次任务中由用户明确授权，不得自动上传或静默降级。
- 联网仅用于模型/LoRA 官方资料研究、补充社区资料和检查版本更新。

## 4. 第一阶段主流程

1. 用户输入中文创意、参考图片，或两者的组合。
2. 系统提取核心意图、可见画面信息和不确定项。
3. 用户确认少量会明显改变方向的冲突或歧义。
4. 系统选择当前 Anima 模型档案，并推荐最小必要 LoRA 组合。
5. 用户确认模型、LoRA 和关键偏好。
6. 系统生成模型适配后的正向提示词、负向提示词和基础参数。
7. 用户用中文提出局部修改，系统预览受影响结构块及前后差异。
8. 用户确认应用，系统生成新版本并锁定未点名内容。
9. 用户逐项或整组复制完整配方到 Anima，手动出图。
10. 用户保存满意版本、可复用组件和配套示例图片。

## 5. 输入理解需求

### 5.1 模糊中文创意

- 保留用户明确表达的主体、题材和情绪方向。
- 主动补全构图、镜头、环境、光影和必要画面细节。
- 不得擅自改变主体、题材或情绪方向。
- 对低风险细节可以直接补全；对会显著改变成图方向的歧义，提供少量清晰候选供用户选择。
- 不把每次创作变成连续问答。

### 5.2 参考图片

- 输入可能是普通照片、插画、截图或 AI 图片，不假定存在原始提示词或可用元数据。
- 目标不是还原图片原本的提示词，而是尽量保真识别实际可见内容。
- 识别范围包括：主体、人物特征、服装、动作、构图、镜头、环境、光影、画风、道具和特效。
- 看不清或无法确定的内容不得擅自脑补。
- 没有额外文字要求时，尽量保留所有可见信息。

### 5.3 图片与文字共同输入

- 明确文字要求优先，只覆盖文字点名修改的部分。
- 图片中未被文字修改的主体特征、动作、构图、环境、光影和画风应尽量保留。
- 支持“只参考构图和光影”“保留姿势，替换服装与场景”等范围指令。
- 系统应将文字要求映射到结构块，并明确展示哪些内容保留、哪些内容允许修改。

### 5.4 多模型视觉分析

多模型结果不能只做原文拼接，应整理为：

- 已确认：多模型一致或证据充分，可直接进入结构块。
- 有冲突：模型结论不一致，需要用户确认或选择。
- 不确定：画面证据不足，默认不写入确定性描述。

每项结论应保留来源模型和原始输出，方便回看与纠错。

### 5.5 多人物画面

- 每个人物建立独立角色卡，包括身份、外观、服装、表情、动作和画面位置。
- 人物之间的接触、视线和动作关系单独存入“互动关系”结构块。
- 修改一个人物时，其他人物和互动关系默认锁定；若修改会破坏互动关系，必须显式提示。

## 6. 结构化提示词与编辑

### 6.1 结构块

完整创意至少拆分为以下可独立锁定和编辑的结构：

1. 人物身份
2. 身体与外观特征
3. 服装与配饰
4. 表情
5. 姿势与动作
6. 人物互动关系
7. 场景与环境
8. 构图与镜头
9. 光影与色彩
10. 风格与艺术家
11. 道具与特效
12. 质量增强
13. 负向约束

单人物、无人物或无互动的任务可以隐藏无关结构块，但数据结构须支持完整模式。

### 6.2 自然语言局部修改

主要编辑方式是中文指令，而不是手工改写整段提示词。例如：

- “只改服装”
- “人物不变，换成俯拍”
- “保留构图，加强夜景氛围”

系统必须：

1. 识别指令对应的结构块。
2. 只修改被点名的内容。
3. 锁定未点名结构块。
4. 在执行前显示将受影响的结构块和前后差异。
5. 经用户确认后应用，并创建新版本。

手工编辑原始提示词继续保留，但不是主要操作路径。

### 6.3 变更可追溯

- 每条已应用的中文指令都应记录原始文字、解析结果、受影响结构块和前后差异。
- 支持撤销、回滚和从历史版本继续编辑。
- 该区域是面向创作变更的指令栏，不设计成通用聊天窗口。

## 7. 完整生图配方

最终输出不是单独一段提示词，而是一份完整配方：

- 基础模型及精确版本
- 正向提示词
- 负向提示词
- LoRA 列表、触发词和权重
- 采样器
- 调度器
- 步数
- CFG
- 分辨率与画幅
- Seed
- 图生图任务的去噪强度

每个字段可单独复制，也可一键复制整份摘要。保存版本时必须保存完整配方，而不是只保存文本结构块。

### 7.1 可复现全随机

全随机使用本地版本化词库作为元素来源，文本模型只负责把代码抽中的元素组织成成立
画面，不负责提供随机熵。产品必须：

- 分开记录 `librarySeed`、可选 `modelSeed` 和最终出图 `generationSeed`。
- 固定目录、抽样器和结构映射版本；同一目录、Seed、配置和锁定项必须得到同一抽取
  计划。
- 展示实际抽中项、来源、绑定结构块、确定性重抽、拒绝原因和软冲突。
- 硬约束不得由模型静默替换或丢弃；锁定项冲突必须交给用户选择。
- 保存最终结构块和输出以及完整随机轨迹。旧目录缺失时仍可打开历史版本，只禁用基于
  旧目录重新抽取。
- 客户端提交词条 ID 时由服务端在指定目录重新解析，不信任客户端提供的词条文本、
  文件路径或结构映射。

首版随机 profile 只支持成年人物场景；非人、无人和多人物随机在逐条兼容性审查和
十三块结构完成前不开放。

## 8. 模型档案与参数建议

### 8.1 第一阶段支持范围

- 第一阶段只正式支持 Anima。
- 首个基准档案为 `MiaoMiao Harem Anima_1.1`，版本 ID `3004063`。
- 架构允许以后新增其他模型，但不得为未验证模型伪造规则。
- 默认正向前缀不得加入 `safe`。
- 内容模式只由用户显式切换，系统不得从模糊创意或图片自动推断并切换。

### 8.2 模型档案字段

- 模型名称、文件标识、精确版本和哈希
- 提示词语法、偏好、排序和支持/禁用语法
- 固定正向前缀、后缀和负向提示词
- 推荐采样器、调度器、步数、CFG 和已验证尺寸
- 兼容的 LoRA 类型和已知冲突
- 官方来源、社区经验、本地验证结论及各自证据等级

### 8.3 Anima_1.1 初始基线

以下内容作为待本地验证的初始档案，不应被描述为永久规则：

- 正向前缀：`masterpiece, best quality, score_7`
- 可选增强：`very aesthetic, ultra-detailed, high contrast`
- Steps：30
- CFG：4.0–6.0，默认 5.5
- 采样组合：Euler Normal 或 Euler a Normal
- 尺寸：只能从已验证尺寸预设中推荐；系统可根据构图建议，用户可覆盖。

### 8.4 参数优先级与来源

配方合成优先级从高到低为：

1. 当前任务手动覆盖
2. 任务预设
3. LoRA 兼容性要求
4. 模型默认值

每个最终参数应显示来源。系统不得无提示地覆盖用户值。

### 8.5 基础与高级参数

默认创作界面展示：画幅/分辨率、采样器、调度器、步数、CFG、Seed，以及需要时的去噪强度。

高清修复、二次采样、分块放大和放大模型可作为高级配方保存，但第一阶段不自动设计复杂工作流。

## 9. LoRA 管理与推荐

### 9.1 LoRA 是一等资产

LoRA 不作为普通标签处理。每条 LoRA 记录至少包含：

- 文件身份、路径和哈希
- 精确基础模型兼容关系
- 主分类和辅助标签
- 触发词
- 推荐权重及范围
- 提示词位置和顺序
- 兼容或冲突的 LoRA
- 官方链接、精确版本和作者说明
- 单独标注的社区经验与本地测试结论
- 示例图片

### 9.2 分类

内置主分类包括：角色、风格/艺术家、服装、姿势/动作、表情、身体特征、场景/建筑、光影/色彩、构图/镜头、道具/特效和细节增强。

每个 LoRA 有一个主分类、多个辅助标签。系统可以给候选分类，但由用户确认；允许自定义分类。

### 9.3 本地目录扫描

- 支持配置多个模型和 LoRA 目录。
- 扫描采用增量方式，只读索引，不移动、重命名或删除原文件。
- 新文件进入“待审核”。
- 路径失效时标记缺失，不删除历史记录；可通过哈希重新关联。
- 优先读取本地文件和旁车元数据，不得只根据文件名推断可信触发词。
- 缺少信息时生成候选，等待用户确认。

### 9.4 推荐逻辑

- 在理解创意或图片后，推荐一个基础模型和最少必要的 LoRA 组合。
- 同类型 LoRA 重叠时优先推荐一个主 LoRA，并说明理由；只有互补时才建议混用。
- 硬规则先过滤版本不兼容、类型冲突和权重越界；AI 再结合创意、参考图和历史偏好排序。
- 推荐必须展示触发词、建议权重、冲突、互补关系和选择理由。
- 系统不得自动删除、替换或启用 LoRA。

### 9.5 个性化

- 本地记录历史选择的模型、LoRA、权重、参数和已保存配方。
- 相似任务可优先展示历史有效组合。
- 个人偏好与通用模型规则分开保存。
- 一次使用不得直接变成永久默认值。

## 10. 模型与 LoRA 资料研究

### 10.1 新增资料流程

新增模型或 LoRA 时，用户提供官方/作者链接和精确版本。系统建立待审核研究任务并收集：

- 基础模型、版本与哈希
- 触发词、推荐权重和提示词写法
- 推荐参数、兼容关系和已知冲突
- 擅长与不擅长的题材
- 示例提示词
- 许可与使用条件

研究结果先进入待审核档案，用户确认后才能成为正式规则；不得静默覆盖已经确认的档案。

### 10.2 证据分级

1. 官方模型页、官方仓库和作者说明
2. 作者教程与发布记录
3. 经过交叉验证的社区测试、教程和讨论
4. 尚未验证的单一来源说法

重要结论必须保留来源链接和证据等级。社区信息明确标为“社区经验”，未知结论标为“待测试”。

### 10.3 版本更新

- 支持手动检查和可配置的定期检查。
- 新版本建立独立档案，不覆盖旧版本。
- 生成差异报告，突出触发词、参数和兼容性变化。
- 用户确认后才能迁移任务预设和 LoRA 配方。

### 10.4 本地验证闭环

系统可生成测试矩阵，包括无 LoRA 基线、触发词对比、权重扫描、提示词强度和兼容组合。用户在外部 ComfyUI/Anima 中手动测试并上传代表结果。

正式档案应将“官方建议”“社区经验”“本机实测结论”分开保存，后续推荐优先采用本机实测结论。

## 11. 资产库与配套图片

### 11.1 可保存内容

- 完整生图配方
- 人物、服装、动作、场景、构图、光影、风格等可复用组件
- LoRA 组合与参数预设
- 一张封面图和多张补充示例图

复用时创建副本，不覆盖原始已确认资产，并保留适用模型、LoRA 和参数范围。

### 11.2 图片用途

- 资产图片默认只用于展示、搜索和人工参考，不自动分析或改写提示词。
- 只有用户明确点击“以此图为参考创作”时，才启动图片分析流程。

### 11.3 本地存储

- 图片复制到 Prompt Studio 管理的本地资产目录。
- 创建缩略图，并通过文件哈希去重。
- 数据库只存记录和路径，不存二进制图片。
- 删除资产时单独询问是否同时删除本地图片。

### 11.4 检索

- 缩略图优先浏览和关键词搜索。
- 支持按基础模型、LoRA 类型、主题、人物、风格、场景、资产类型、收藏和最近使用筛选。
- 自动标签只作为候选，用户可以确认、修改或删除。

## 12. 项目与版本管理

- 首次生成、应用中文修改、切换模型/LoRA、修改关键参数时自动创建版本。
- 普通输入过程不创建版本。
- 支持命名里程碑，如“成稿”“人物版”“夜景版”。
- 关闭或刷新后可以从项目库重新打开，并基于历史版本继续编辑。
- 每个版本保存完整配方、结构块、修改指令、来源和配套图片关联。

## 13. 备份与恢复

备份包包含：

- Prompt Studio 数据库
- 模型和 LoRA 档案
- 研究来源与手工修订
- 配方、结构组件和资产图片

备份包不包含模型文件、LoRA 文件和 API 密钥。恢复后重新扫描本地模型目录，并通过哈希重建关联。

## 14. 界面信息架构

### 14.1 创作工作台

默认只展示当前模型、推荐 LoRA、核心提示词和基础参数。

以下内容按需展开：结构块、建议理由、资料来源、冲突与不确定项、高级参数、历史版本和指令记录。

### 14.2 资料与资产管理

独立管理界面负责：

- 模型/LoRA 扫描和待审核队列
- 官方链接研究和资料审核
- 版本更新差异
- 资产库搜索、批量管理和备份恢复

## 15. 离线、隐私与可靠性

- 离线时仍可使用已建立的档案、LoRA 选择、本地 LLM 生成、图片分析、中文局部修改、参数建议和资产管理。
- 联网研究结果应缓存到本地，离线时可查看。
- 调用外部 API 前显示提供方和将发送的数据，按任务单次授权。
- 不允许外部 API 自动兜底。
- 长任务显示真实进度；取消操作必须能中断后端推理，而不只是停止前端等待。

## 16. 第一阶段明确不做

- 不接入 ComfyUI 自动出图、队列控制或参数同步。
- 不做生成结果的自动对比评分，效果由用户自行判断。
- 不做注册、多用户、云同步、移动端和新手教程。
- 不训练、合并、下载、移动或删除模型/LoRA 文件。
- 不做全模型通用适配；只正式支持 Anima_1.1。
- 不自动设计高清修复、二次采样、放大等复杂工作流。

## 17. 当前实现与目标需求的边界

本文件描述目标产品，不代表全部已经实现。截至 2026-07-26，当前仓库已完成以下可运行
底座：

- 十三块工作台与 Recipe v1。每个新版本内嵌模型引用、双语提示词、参数及来源、LoRA
  选择快照、随机轨迹、中文修改历史、图片/来源引用和严格 Hash。
- 统一创意导演首页、最多八张参考图用途/来源追溯、确认 brief、精确模型档案研究与
  十三块适配交接，以及 LoRA-lite 元数据档案和显式兼容门禁。
- Anima_1.1 档案绑定版本 ID `3004063`，默认 Steps 30、CFG 5.5、Euler/Euler a +
  Normal，不注入 `safe`；未验证的 checkpoint Hash 和尺寸不会伪装为可用推荐。
- 项目头与版本一次原子保存，稳定幂等键覆盖响应丢失重放；项目列表、完整重开、历史
  继续编辑和连续版本已打通。
